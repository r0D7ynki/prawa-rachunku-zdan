## Goal
W trybie ciemnym nic nie jest nieczytelne. Wszystkie komponenty biorą kolory z tokenów motywu.

## Context
Uwaga właściciela: „jak dodałeś tryb ciemny, to rzeczy w tabelkach zaznaczone na mega jasno
nie pasują, bo białego tekstu w ogóle nie widać”.

**Przyczyna:** `app.css` w ciemnym motywie zmienia tylko tło strony i kolor tekstu.
Komponenty (`truth-table.css`, `wizualizacje.css`, `playground.css`, `quiz.css`, `steps.css`,
`stepper.css`, `reguly.css`, `dowody.css`, `rezolucja.css`, `nawigacja.css`, `motyw.css`)
mają kolory wpisane na sztywno (`#fff`, `#f7f7fb`, `#ece9ff`, `white`). W trybie ciemnym
zostaje jasne tło komórki i jasny tekst — treść znika.

Zadanie:
1. **Tokeny motywu** w `app.css`: `:root` = jasny, `[data-theme="dark"]` = ciemny.
   Nazwy: `--tlo`, `--tlo-panel`, `--tlo-panel-2`, `--tekst`, `--tekst-muted`, `--ramka`,
   `--akcent`, `--akcent-tekst`, `--prawda`, `--prawda-tlo`, `--falsz`, `--falsz-tlo`,
   `--formula-tlo`, `--komorka-tlo`, `--komorka-obramowanie`, `--cien`. Te same nazwy w obu motywach.
2. **Każdy plik CSS komponentu** używa wyłącznie tokenów: żadnego `#fff`, `#ffffff`, `white`,
   `#000`, `black` poza `app.css`.
3. **Komórki oceny** (`komorka-dobrze`, `komorka-zle`): tło z `--prawda-tlo` / `--falsz-tlo`,
   tekst z `--prawda` / `--falsz`, kontrast tekstu do tła co najmniej 4.5:1 w obu motywach.
4. **Diagramy SVG**: obszary i obrysy z tokenów, napisy z `--tekst`; w trybie ciemnym obszary
   nie mogą być jaśniejsze niż tło panelu.
5. **Alerty i plakietki** Bootstrapa: własne kolory z tokenów, czytelne w obu motywach.
6. **Test kontrastu** (`tests/test_kontrast.py`): wczytaj `app/static/css/app.css`, wyciągnij
   wartości tokenów dla `:root` i `[data-theme="dark"]`, policz współczynnik kontrastu WCAG
   dla par: `--tekst`/`--tlo`, `--tekst`/`--tlo-panel`, `--tekst-muted`/`--tlo-panel`,
   `--prawda`/`--prawda-tlo`, `--falsz`/`--falsz-tlo`, `--akcent-tekst`/`--akcent`.
   Każda para w obu motywach ≥ 4.5. Komunikat błędu podaje parę, motyw i wynik.

## Evidence

### Co powstało

- `app.css`: komplet szesnastu tokenów w `:root` (motyw jasny) i w `:root[data-theme="dark"]`
  (wybór użytkownika) oraz **kopia wartości ciemnych** w `@media (prefers-color-scheme: dark)`
  pod `:root:not([data-theme])` — dla czytelnika bez JavaScriptu, któremu serwer nie wpisuje
  `data-theme`. CSS nie pozwala objąć jednym blokiem atrybutu i zapytania o media, dlatego
  zgodności obu zestawów pilnuje `test_tryb_systemowy_ma_te_same_tokeny_co_wybor_uzytkownika`.
- Alerty i plakietki: `.alert-info`/`-success`/`-danger` oraz `.badge.text-bg-secondary`
  biorą kolory z tokenów, a przyciski odpowiedzi w `quiz.css` — przez zmienne `--bs-btn-*`.
  `alert-warning` zostaje przy parach kolorów z PRZ-138: motyw nie ma tokenu ostrzeżenia.
- Wszystkie arkusze komponentów: kolory wpisane wprost zastąpione tokenami (`#fff` →
  `--tlo-panel`, `#6b6880` → `--tekst-muted`, `--bs-primary-bg-subtle` → `--formula-tlo`,
  `--bs-danger-bg-subtle` → `--falsz-tlo`, `#ffffff`/`#10121f` w rysunkach → `--tlo-panel`).
  Z `wizualizacje.css` zniknął cały lokalny blok `@media (prefers-color-scheme: dark)` —
  rysunki idą za tokenami, więc reagują też na wybór użytkownika, nie tylko na system.
- `app.css`: usunięta łata `:root .karta-reguly, …` — była poprawką na czas, aż arkusze
  wezmą `var(--…)`. Kopia łaty w `motyw.css` zostaje (poza zakresem karty) — „Do zgłoszenia”.

### Czytelność stron w obu motywach (sprawdzone wzrokowo, chromium z cache Playwrighta)

Aplikacja na `127.0.0.1:5099`, zrzuty w `/tmp/prz139-strony/`. Motyw ciemny wymuszony
`--force-dark-mode` (emulacja `prefers-color-scheme: dark`; strona deklaruje
`<meta name="color-scheme" content="light dark">`, więc przeglądarka nie odwraca kolorów
sama). Dla wariantu **bez JavaScriptu** zapisałem HTML z serwera i wyciąłem ze niego
`<script>` — wtedy nie ma znacznika `data-theme`, więc działa blok `@media`.

| Strona | Jasny | Ciemny (wybór i system) | Bez JavaScriptu + system ciemny |

| `/prawa/wylaczony-srodek` | ✓ | ✓ | ✓ (sekcje, wzory, kroki, plakietki) |
| `/tautologie` | ✓ | ✓ | ✓ (tabele krokowe) |
| `/quiz` | ✓ | ✓ | ✓ (formularz ustawień) |
| `/plac-zabaw` | ✓ | ✓ | ✓ |

Na co patrzyłem: komórki tablicy prawdy i oceny wpisu (✓/✕), wybrany wiersz i kolumna,
alerty, plakietki kroków, przyciski odpowiedzi quizu, kroki przekształcania z wyróżnionym
fragmentem, wiersze dowodu (bieżący, źródło, sprzeczność), karty reguł i schematy, nawigacja
oraz oba rysunki SVG (bramki i zbiory). Zrzut `ciemny.html` (z `data-theme="dark"`)
i `ciemny-system.html` (bez `data-theme`, `--force-dark-mode`) wyszły **co do bajtu takie
same** (`md5sum` → `ba23938b…`) — obie ścieżki malują to samo.
