`app/logic/rules.py`:

```python
@dataclass(frozen=True)
class Rule:
    kod: str            # "RO", "OK", "DK", "OA", "DA", "DR", "OR", "DM1", "DM2", "KP"
    nazwa: str          # "Reguła odrywania"
    pelna_nazwa: str    # "Modus Ponens" albo ""
    typ: str            # "pierwotna" | "dodatkowa"
    przeslanki: list[str]   # ["Φ → Ψ", "Φ"]
    wniosek: str            # "Ψ"
    tautologia: str         # "((p → q) ∧ p) → q"
    przyklad: str
    opis: str               # 1-2 zdania prostym językiem

def rules() -> list[Rule]     # pierwotne wg tabeli, potem dodatkowe
def get(kod: str) -> Rule | None
```

### Decyzje i uwagi dla review

* **Dwa pola spoza kontraktu karty**: `Rule.wnioski_dodatkowe` i `Rule.tautologie_dodatkowe`.
  Wykład podaje OK i OR w dwóch wersjach (`Φ ∧ Ψ ⊢ Φ`/`⊢ Ψ` oraz `Φ ≡ Ψ ⊢ Φ → Ψ`/`⊢ Ψ → Φ`),
  a dla OK — dwie osobne tautologie. Sklejenie ich w jedno pole dawałoby napis, który nie jest
  formułą. Oba pola opisane w `docs/ARCHITEKTURA.md` (razem z powodem) i sprawdzone testem
  `test_dwie_reguly_maja_po_dwie_wersje_wniosku`.
* **Przykłady dla DM1, DM2, KP** nie istnieją w tabeli wykładu (nie ma tam kolumny „Przykład”),
  a kryterium wymaga niepustego pola. Trzy przykłady dopisane w stylu wykładu (śnieg/zimno);
  pilnuje tego `test_przyklady_regul_dodatkowych_sa_zdaniami_o_tej_samej_regule`. Tautologie,
  przesłanki, wnioski, nazwy i pozostałe przykłady są porównywane z `docs/TRESC-WYKLAD2.md`
  testem `test_przeslanki_wnioski_i_tautologie_pochodza_z_wykladu`.
* **Metazmienne `Φ`/`Ψ` nie są formułami dla parsera** (przyjmuje nazwy ASCII). Widok zamienia
  je na litery przed `formula.parse` i wraca do nich w drzewie przez `formula.replace` —
  dzięki temu spójniki mają te same klasy HTML (`op-imp`, `op-and`), co na innych stronach.
  Test `test_metazmienne_to_html_nie_gubi_znakow_ani_kolejnosci` sprawdza, że napis wraca
  znak w znak.
* Karta reguły nie linkuje do stron wykładu 2, których jeszcze nie ma (`/dowody`, `/konsekwencja`)
  — `base.html` celowo używa zwykłych `href`, ale odnośnik do nieistniejącej strony prowadziłby
  użytkownika do 404.
