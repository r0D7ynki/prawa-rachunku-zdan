## Goal
Powstaje strona `/rezolucja`: reguła rezolucji, literały, algorytm i dwa przykłady z wykładu
przechodzone krok po kroku, ze strzałkami od klauzul rodziców do klauzuli wynikowej.

## Context
Treść: `docs/TRESC-WYKLAD2.md`, sekcje „6. Reguła rezolucji” i „7. Algorytm rezolucji”.
Oba przykłady (11 wierszy i 7 wierszy) są tam wypisane razem z kolumną „Skąd”.

Dane w `app/logic/resolution.py` (nowy plik):

```python
@dataclass(frozen=True)
class ResolutionStep:
    nr: int
    klauzula: str       # "q ∨ r"
    rodzice: list[int]  # [1, 3]
    literal: str        # "p" — na czym sklejono; "" dla założeń i sprzeczności
    rodzaj: str         # "zalozenie" | "negacja-tezy" | "rezolucja" | "sprzecznosc"

@dataclass(frozen=True)
class ResolutionProof:
    id: str
    tytul: str
    opis: str
    kroki: list[ResolutionStep]

def proofs() -> list[ResolutionProof]
```

Strona `/rezolucja`:
1. Reguła rezolucji: schemat z kreską, wyjaśnienie „literał”, przykład z wykładu
   (`p ∨ ∼r ∨ q ∨ s` i `p ∨ t ∨ ∼q` dają `p ∨ ∼r ∨ s ∨ t`).
2. Algorytm w czterech krokach (lista numerowana) + przypomnienie, że KPN omawia wykład 1
   (odnośnik `/kpn`).
3. Dwa przykłady z wykładu: tabela klauzul (nr, klauzula, skąd, literał).
4. Pasek kroków (komponent PRZ-072): krok po kroku dodaje wiersz; **strzałki** prowadzą od
   klauzul `rodzice` do nowej klauzuli, a etykieta strzałki podaje literał sklejenia
   („na p”). Ostatni krok podświetla dwa sprzeczne wiersze.
5. Bez JavaScriptu: całe tabele widoczne od razu.
