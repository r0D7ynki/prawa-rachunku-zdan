## Goal
Tablice dowodowe na `/tautologie` powstają krok po kroku. Strzałki pokazują, z których kolumn
powstaje wynik, a metoda skrócona zawęża tabelę w widoczny sposób.

## Context
Uwaga właściciela: „super pomysł, że do tautologii dałeś wizualizacje, ale dodaj strzałki,
żeby można to rozbić krok po kroku”. Ta karta dotyczy strony `/tautologie` (karta PRZ-020)
i komponentu kroków (PRZ-072).

Zakres:
1. **Tabela `((p → q) ∧ ∼q) → ∼p`** (cztery wiersze, kolumny `p`, `q`, `p → q`, `∼q`,
   `α = (p → q) ∧ ∼q`, `∼p`, `α → ∼p`):
   - na starcie widoczne są tylko kolumny `p` i `q`,
   - kolejne kroki odkrywają kolumny od lewej do prawej,
   - nad tabelą rysowana jest **strzałka** od każdej kolumny źródłowej do nowo liczonej
     (np. od `p` i `q` do `p → q`); strzałka ma opis operacji („implikacja”),
   - pod tabelą opis kroku: „Kolumna α: koniunkcja (p → q) i ∼q. W wierszu 3: 0 ∧ 1 = 0”,
   - ostatni krok dodaje wiersz podsumowania: „Wszystkie wiersze mają 1 — to tautologia”.
2. **Metoda skrócona** dla `((p → q) ∧ (q → r)) → (∼r → ∼p)`:
   - krok 1: cała tabela ośmiu wierszy,
   - krok 2: odrzucamy wiersze, w których formuła **nie może** być fałszywa — odrzucone wiersze
     gasną (klasa `wiersz-odrzucony`), z opisem „Zostają tylko przypadki, w których ∼r → ∼p
     jest fałszywa: r = 0 i p = 1”,
   - krok 3: zostają dwa wiersze z kolumnami `α`, `β`, `γ`, `δ` i wynikiem `γ → δ`,
   - krok 4: wniosek „W obu przypadkach wynik to 1. Formuła jest tautologią.”,
   - każdy krok ma strzałkę albo strzałkę „zawężenie” pokazującą, które wiersze odpadły.
3. Paski kroków z komponentu („Dalej”, „Wstecz”, „Od nowa”, „Odtwórz/Pauza”).
4. Bez JavaScriptu: obie tabele są w HTML w pełnej wersji (jak dziś) — kroki tylko je ujawniają.

Implementacja: nowy `app/static/js/tautologie.js` (nowy plik), zmiany w szablonie i widoku.
Kroki buduj w Pythonie (`app/blueprints/tautologie.py`) i przekaż do szablonu jako JSON
w `data-kroki` — JavaScript tylko pokazuje i ukrywa.
