## Goal
Powstaje widok `app/blueprints/api_formula.py` z endpointami `/api/formula/parse`,
`/api/formula/table` i `/api/equivalence`. To jedyne źródło danych dla komponentów JavaScript.

## Context
Kontrakt: `docs/ARCHITEKTURA.md`, sekcja „API”, akapit `api_formula.py`. Zasady:
- każdy endpoint to `POST` z JSON-em; błędne dane dają `ok: false`, pole `blad` po polsku
  i kod HTTP 200 (nie 500),
- brak danych wejściowych, zły typ pola i nieparsowalna formuła to błąd danych, nie awaria,
- `/api/formula/parse` zwraca dodatkowo `ast` — drzewo JSON wg kontraktu. Rysunki bramek
  i diagramy zbiorów (PRZ-012) budują się z tego drzewa,
- `/api/formula/table` przyjmuje `podformuly` (domyślnie `True`),
- `Content-Type` odpowiedzi to `application/json`.
- Blueprint: `bp = Blueprint("api_formula", __name__, url_prefix="/api")` — nazwa blueprintu musi
  być unikalna, bo inne karty dodają własne moduły API.
- `/api/formula/parse` zwraca trzy zapisy formuły: `wyklad` i `unicode` (tekst) oraz `ascii`.
  Pole `wyklad` używa `∼` i `≡`, pole `unicode` używa `¬` i `↔`. Komponenty JavaScript
  (PRZ-011, PRZ-012, PRZ-013) pokazują najpierw zapis z pola `wyklad`.
- `table` w odpowiedzi zawiera dodatkowo `znaki`: listę wierszy z wartościami `1`/`0`
  zamiast `true`/`false` — na stronie pokazujemy `1`/`0` jak na wykładzie.

Zabezpieczenia:
- limit długości formuły: 500 znaków; dłuższa formuła to `ok: false` z komunikatem,
- limit zmiennych obsługuje `truth.build` (6) — przekaż komunikat błędu do `blad`.

## Acceptance criteria
- [x] `POST /api/formula/parse` z `{"formula": "p -> q"}` zwraca `ok: true`, `wyklad` i `unicode` równe `p → q`, `ascii`, `html`, `ast` i `zmienne == ["p", "q"]`.
- [x] `POST /api/formula/parse` z `{"formula": "∼(p ∨ q)"}` zwraca `wyklad` zaczynający się od `∼` i `unicode` zaczynający się od `¬`.
- [x] `ast` dla `p -> q` to `{"typ": "Imp", "lewy": {"typ": "Var", "nazwa": "p"}, "prawy": {"typ": "Var", "nazwa": "q"}}`.
- [x] `ast` dla `¬(p ∧ q)` ma `typ: "Not"` i dziecko `typ: "And"`.
- [x] `POST /api/formula/table` z `{"formula": "p ∧ q"}` zwraca `ok: true`, `klasyfikacja == "spełnialna"` i tabelę z 4 wierszami.
- [x] `POST /api/formula/table` z `{"formula": "p ∨ ¬p"}` zwraca `klasyfikacja == "tautologia"`.
- [x] Pole `znaki` w odpowiedzi `table` zawiera dla `p ∧ q` wiersz z wartościami `0`/`1`, nie `true`/`false`.
- [x] `POST /api/equivalence` z `{"lewa": "p → q", "prawa": "¬p ∨ q"}` zwraca `rownowazne: true`. Dla `p ∧ q` i `p ∨ q` zwraca `rownowazne: false` oraz `kontrprzyklad` z wartościami zmiennych.
- [x] Formuła `"p ∧"`, brak pola `formula`, pole `formula` jako liczba i formuła 501 znaków dają `ok: false`, niepuste `blad` i kod HTTP 200.
- [x] Odpowiedź ma nagłówek `Content-Type` zaczynający się od `application/json`.
- [x] `tests/test_api_formula.py` używa `create_app({"TESTING": True}).test_client()` i sprawdza wszystkie powyższe przypadki.
