## Goal
Diagram zbiorów dla praw de Morgana pokazuje kolejne kroki przekształcenia, a nie tylko dwa
gotowe obrazki. Na każdym kroku widać, który fragment formuły właśnie zamalowujemy.

## Context
Uwaga właściciela: „wynik końcowy niewiele daje — pokaż, jak po kolei to idzie”.
Komponent kroków: `stepper.js` (PRZ-072). Kroki bierze z pola `kroki` prawa (`laws.py`) —
te same opisy, które są na stronie prawa, żeby teoria i rysunek się zgadzały.

Zachowanie:
- na górze diagram lewej strony prawa, obok diagram prawej strony,
- pasek kroków pod diagramami; każdy krok odpowiada jednemu wpisowi `kroki` prawa,
- **kolejność kroków wynika z kolejności wykonywania operacji na zbiorach**: idziemy od
  operacji najbardziej wewnętrznej do zewnętrznej. Dla `∼(p ∨ q)` najpierw widać **sumę**
  zbiorów, potem **dopełnienie** tej sumy. Dla `∼p ∧ ∼q` najpierw **dopełnienie** każdego
  zbioru, potem **część wspólną** dopełnień,
- nazwa operacji jest wypisana wprost nad diagramem: „część wspólna”, „suma”, „dopełnienie”,
  plus krótkie wyjaśnienie, co to znaczy dla zaznaczonego obszaru,
- na kroku `i` zamalowany jest obszar odpowiadający formule z kroku `i`, a poprzednie obszary
  zostają widoczne jako obrys (żeby student widział, że to ten sam obszar),
- bieżąca zmiana jest opisana pod diagramem: „Krok 2: dopełnienie sumy — obszar poza sumą
  zbiorów”,
- **strzałka** między diagramami pokazuje przejście „lewa strona ≡ prawa strona”,
- przełącznik „Pokaż oba naraz” pokazuje docelowy stan (jak dziś),
- gdy formuła nie nadaje się do diagramu (więcej niż 3 zmienne albo brak `∼`, `∧`, `∨`),
  partial pokazuje komunikat po polsku i nie rysuje.

Uwaga o rysowaniu: obszary licz na siatce punktów (np. 60×60 próbek), a nie kombinacjami
figur — dla trzech zbiorów siatka daje poprawny wynik bez analitycznej geometrii. Gęstość
siatki dobierz tak, żeby rysunek był gładki, ale generowanie trwało krócej niż 50 ms.

**1. [BLOCKER] obrys wcześniejszego kroku leżał pod wypełnieniem**

Przyczyna: `rysunek.append(obrysy, wypelnienie)` dokładało wypełnienie bieżącego kroku **po**
obrysach. SVG nie zna `z-index` — późniejszy element zasłania wcześniejszy. Przy krokach
równoważnych (krok 3 i krok 1 w de Morganie) oba obszary mają ten sam kształt, więc wypełnienie
zasłaniało dokładnie ten obrys, który miał pokazać „ten sam obszar” (wymaganie karty: „poprzednie
obszary zostają widoczne jako obrys”).

Poprawka — odwrócona kolejność argumentów jednego `append` (plus komentarz w kodzie, żeby nikt
tego nie „posprzątał” z powrotem):

```js
// Najpierw wypełnienie, potem obrysy — inaczej wypełnienie zasłoniłoby obrys
// obszaru o tym samym kształcie (patrz komentarz przy `zbudujDiagram`).
rysunek.append(wypelnienie, obrysy);
```

Dowód w prawdziwej przeglądarce (chromium z cache Playwrighta, `--dump-dom`; stronę i API podał
cienki proxy z `/tmp`, więc `sets.js` w repozytorium działa bez zmian, a projekt nie dostaje
runnera JS). Driver klika kropkę kroku 3 i wypisuje kolejność dzieci lewego SVG:

**2. [FOLLOWUP] krok bez formuły przewracał rysunek**

`drzewa.get(krok.po)` dla pustego `po` daje `undefined`, a `operacja` czyta `undefined.typ`.
Poprawka: kroki prawa idą do rysunku tylko wtedy, gdy każdy ma drzewo; inaczej wracamy do
`krokiZapasowe` (podformuły obu stron).

```js
const krokiPrawaMajaDrzewa =
  krokiPrawa.length > 0 && krokiPrawa.every((krok) => drzewa.has(krok.po));
```
