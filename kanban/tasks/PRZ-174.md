## Goal
Gdy API zawiedzie (błąd serwera, brak sieci), każdy komponent pokazuje komunikat po polsku
zamiast milczeć.

## Context
To najważniejsza grupa uwag z przeglądów (karty `Uwaga z PRZ-011`, `PRZ-014`, `PRZ-012`):
w kilku skryptach `fetch` nie sprawdza `response.ok` przed `response.json()`. Gdy serwer
zwróci 500 albo połączenie padnie, użytkownik widzi pustkę i nie wie, co się stało.

Zadanie — wspólny helper i użycie we wszystkich komponentach:
1. Nowy plik `app/static/js/api.js` eksportujący:

```js
export async function pobierzJson(adres, dane) {
  // zwraca { ok: true, dane } albo { ok: false, blad: "komunikat po polsku" }
}
```

Zachowanie helpera:
- `fetch` w `try/catch` — błąd sieci to `ok: false` z komunikatem
  „Nie udało się połączyć z serwerem. Sprawdź połączenie i spróbuj ponownie.”,
- brak `response.ok` to `ok: false` z komunikatem
  „Serwer zwrócił błąd (kod N). Spróbuj ponownie.”,
- nieparsowalny JSON to `ok: false` z komunikatem „Serwer zwrócił nieprawidłową odpowiedź.”,
- odpowiedź z `ok: false` z API (pole `blad`) przekazuje komunikat z API,
- limit czasu 15 s przez `AbortController` z komunikatem „Serwer nie odpowiedział w porę.”.
2. Wszystkie komponenty korzystają z `pobierzJson` zamiast własnego `fetch`:
   `truth-table.js`, `gates.js`, `sets.js`, `playground.js`, `quiz.js`, `wynikanie.js`,
   `tautologie.js`, `dowody.js`, `rezolucja.js`.
3. Każdy komponent wstawia komunikat błędu do swojego kontenera przez `textContent`
   (nigdy `innerHTML`) i ustawia `role="alert"`.
4. Testy (`tests/test_api_js.py`, nowy): dla każdego pliku komponentu sprawdź, że importuje
   `pobierzJson`, nie wywołuje `fetch(` bezpośrednio i obsługuje `ok: false`.
   Osobny test sprawdza, że `api.js` zawiera obsługę `response.ok`, `AbortController`
   oraz komunikaty po polsku.

## Evidence

### Co powstało

- `app/static/js/api.js` (nowy): `pobierzJson(adres, dane)` z limitem 15 s przez
  `AbortController`. Nigdy nie rzuca — zwraca `{ ok: true, dane }` albo
  `{ ok: false, blad }`, gdzie `blad` jest gotowym komunikatem po polsku
  (sieć, kod HTTP, zły JSON, `ok: false` z API, przekroczony czas).
- Sześć komponentów sieciowych (`truth-table.js`, `gates.js`, `sets.js`, `playground.js`,
  `quiz.js`, `wynikanie.js`) woła wspólnego klienta; własne `fetch(` i `try/catch`
  zniknęły. Każdy komunikat błędu ląduje w kontenerze przez `textContent`,
  a kontener dostaje `role="alert"` (tablica, bramki, zbiory, plac zabaw, quiz, wynikanie
  — razem z wynikiem porównania równoważności).
- Dwa poziomy sprawdzenia zostały rozdzielone i wszędzie takie same: transport i `ok: false`
  z API obsługuje `pobierzJson` (`if (!wynik.ok)`), a komponent nadal sprawdza, czy serwer
  potwierdził sukces w ładunku (`if (!dane.ok)`) — dzięki temu komunikaty komponentów
  („Nie udało się narysować schematu…”) zostają na miejscu.
- `tests/test_api_js.py` (nowy): 34 testy statyczne — kontrakt `api.js` (eksport, limit czasu,
  `AbortController`, komunikaty po polsku, `tresc.ok === false`) oraz użycie klienta
  w każdym komponencie (import, brak `fetch(`, obsługa `ok`, `role="alert"`, brak `innerHTML`).
- `docs/ARCHITEKTURA.md`: nowy rozdział „Wspólny klient API: `api.js`” z kontraktem, tabelą
  komunikatów i uwagą o komponentach krokowych; wiersz `api.js` w mapie kodu i zasada
  „komunikacja z API zawsze przez `api.js`” (AGENTS.md, zasada 2).

### Zmiany poza sekcją Pliki (dopisane do Plików)

Migracja na `pobierzJson` zabiera z plików bezpośrednie `fetch(`, a pięć istniejących testów
miało twarde asercje `assert "fetch(" in <plik>`. Bez ich poprawy bramka nie przechodzi,
więc:

- `tests/test_czesc_tablica.py` — asercja `fetch(` → import `pobierzJson`,
- `tests/test_czesc_wizualizacje.py` (bramki) — `fetch(` → `pobierzJson(`,
- `tests/test_konsekwencja.py`, `tests/test_plac_zabaw.py`, `tests/test_quiz_view.py` —
  `fetch(` → `pobierzJson(`.

Intencja testów została ta sama („skrypt woła API”), zmienił się tylko nośnik żądania.
`tests/test_czesc_kroki.py:324` zostaje przy `fetch(` — dotyczy `steps.js`, którego ta karta
nie obejmuje (patrz „Do zgłoszenia”).

### Trzy komponenty bez sieci (uzgodnione z leadem)

`tautologie.js`, `dowody.js` i `rezolucja.js` nie wykonują żadnego żądania: kroki przychodzą
z serwera w `data-kroki`, a strony nie mają endpointu API (`grep fetch` w tych plikach — brak
trafień). Import `pobierzJson` byłby tam martwym kodem, więc pliki zostają bez zmian;
`tests/test_api_js.py::test_komponent_krokowy_nie_wola_api` pilnuje, żeby nie pojawiło się
w nich ani `fetch(`, ani `pobierzJson(`.

### Weryfikacja w prawdziwej przeglądarce

Testy statyczne nie zauważą błędu składni w `api.js`, a projekt nie ma runnera JS
(AGENTS.md, zasada 6) — dlatego pięć zachowań klienta sprawdziłem chromium
(`~/.cache/ms-playwright/chromium-1243`) na stronie w `/tmp` importującej **kopię**
`app/static/js/api.js`, z mini-serwerem w `/tmp` jako atrapą API:

```
ok: dane={"ok":true,"dane":1}
blad-z-api: blad=Komunikat z API.
http-404: blad=Serwer zwrócił błąd (kod 404). Spróbuj ponownie.
zly-json: blad=Serwer zwrócił nieprawidłową odpowiedź.
limit-czasu: blad=Serwer nie odpowiedział w porę.
```

Limit czasu wyszedł z osobnej strony z atrapą `fetch`, która nigdy nie odpowiada, ale słucha
`signal` — zegar po 15 s przerwał żądanie i dał komunikat o czasie. Tymczasowe serwery
zatrzymałem (porty 5199 i 5202 zwolnione). Nic z `/tmp` nie trafiło do repozytorium.
