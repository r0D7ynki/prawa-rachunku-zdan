## Goal
Powstaje workflow GitHub Actions, który uruchamia `./scripts/gate.sh` przy każdym pushu
i pull requeście. Repo pokazuje zielony znacznik jakości.

## Context
Repo jest publiczne (`r0D7ynki/prawa-rachunku-zdan`). Bramka lokalna to `./scripts/gate.sh`
(ruff, pytest, walidacja kart). Ten sam skrypt ma działać w CI, żeby zielony wynik był widoczny
na GitHubie.

Wymagania workflow:
- plik `.github/workflows/gate.yml`,
- wyzwalacze: `push` na `main` i `swarm/integration` oraz `pull_request`,
- kroki: checkout, `astral-sh/setup-uv@v5` z `enable-cache: true`, `uv sync --frozen`,
  `./scripts/gate.sh`,
- Python z pliku `.python-version` albo `python-version: "3.11"`,
- brak sekretów i brak zmiennych środowiskowych z kluczami,
- `permissions: contents: read`,
- limit czasu 15 minut.

Uwaga: `./scripts/gate.sh` uruchamia też `python3 scripts/kanban/kanban.py check`.
W CI karty są obecne w repo, więc ten krok przejdzie.

## Files
- `.github/workflows/gate.yml` (new)
- `README.md`
- `tests/test_ci_workflow.py` (new)

### 4. PyYAML — świadomie bez nowej zależności

`pyyaml` nie ma w projekcie i **nie dodaję go**: AGENTS.md (twarda zasada 1) mówi „tylko
`flask` w `pyproject.toml`”, a CLAUDE.md każe zgłaszać `[BLOCKER]` za nową zależność.
Karta sama dopuszcza wtedy „`json`/regeks”. Dlatego test czyta plik jako tekst (własny
czytnik bloków YAML), a **dodatkowo** uruchamia `yaml.safe_load`, gdy PyYAML jest dostępny:

```
$ uv run --with pyyaml pytest tests/test_ci_workflow.py
7 passed in 0.01s

$ uv run --with pyyaml python -c "import yaml,pathlib; print(yaml.safe_load(pathlib.Path('.github/workflows/gate.yml').read_text())['jobs'])"
{'gate': {'name': 'Bramka', 'runs-on': 'ubuntu-latest', 'timeout-minutes': 15, 'steps': [{'name': 'Pobranie kodu', 'uses': 'actions/checkout@v5'}, {'name': 'Instalacja uv', 'uses': 'astral-sh/setup-uv@v5', 'with': {'enable-cache': True, 'python-version': '3.11'}}, {'name': 'Zależności', 'run': 'uv sync --frozen'}, {'name': 'Bramka projektu', 'run': './scripts/gate.sh'}]}}

$ uv run --frozen python -c "import yaml"
ModuleNotFoundError: No module named 'yaml'
```

Gałąź z `yaml.safe_load` naprawdę się wykonuje — po podmianie klucza `pull_request:` na
`pull_request_x:` test padł właśnie w niej:

```
>       assert set(wyzwalacze) == {"push", "pull_request"}
E       AssertionError: assert {'pull_request_x', 'push'} == {'pull_request', 'push'}
```

Dlatego wiersz weryfikacji z karty (`uv run python -c "import yaml, ..."`) wymaga
`uv run --with pyyaml python -c ...`; pozostałe dwa wiersze działają bez zmian.

### 5. Uwagi do DoD

- Brak `secrets.`, brak kluczy, brak nowych uprawnień; `permissions: contents: read`.
- Brak nowych zależności projektu — więc nie ma czego wpisywać do `docs/DECISIONS.md`;
  wpis pomijam też dlatego, że przy trzech workerach równolegle kolidowałby numeracją „D”.
- `.python-version` w repo nie ma, więc workflow ustawia `python-version: "3.11"`
  (zgodnie z `requires-python = ">=3.11"`), a `astral-sh/setup-uv@v5` ma `enable-cache: true`.
- CI uruchamia ten sam `./scripts/gate.sh` co lokalnie, łącznie z `kanban.py check`.
