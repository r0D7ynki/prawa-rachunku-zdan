## Goal
Powstaje workflow GitHub Actions, który uruchamia `./scripts/gate.sh` przy każdym pushu
i pull requeście. Repo pokazuje zielony znacznik jakości.

## Context
Repo jest publiczne (`r0D7ynki/prawa-rachunku-zdan`). Bramka lokalna to `./scripts/gate.sh`
(ruff, pytest, walidacja kart). Ten sam skrypt ma działać w CI, żeby zielony wynik był widoczny
na GitHubie.

Wymagania workflow:
- plik `.github/workflows/gate.yml`,
- wyzwalacze: `push` na `main` i `swarm/integration` oraz `pull_request`,
- kroki: checkout, `astral-sh/setup-uv@v5` z `enable-cache: true`, `uv sync --frozen`,
  `./scripts/gate.sh`,
- Python z pliku `.python-version` albo `python-version: "3.11"`,
- brak sekretów i brak zmiennych środowiskowych z kluczami,
- `permissions: contents: read`,
- limit czasu 15 minut.

Uwaga: `./scripts/gate.sh` uruchamia też `python3 scripts/kanban/kanban.py check`.
W CI karty są obecne w repo, więc ten krok przejdzie.

## Files
- `.github/workflows/gate.yml` (new)
- `README.md`
- `tests/test_ci_workflow.py` (new)

## Acceptance criteria
- [ ] Plik `.github/workflows/gate.yml` istnieje i parsuje się jako YAML (`yaml.safe_load` w teście).
- [ ] Workflow ma wyzwalacze `push` i `pull_request` oraz `permissions: contents: read`.
- [ ] Workflow zawiera kroki: `actions/checkout`, `astral-sh/setup-uv`, `uv sync --frozen` i `./scripts/gate.sh`.
- [ ] Workflow nie zawiera żadnego klucza, tokenu ani `secrets.`.
- [ ] `README.md` ma sekcję „CI” z jednym zdaniem i znacznikiem (badge) workflow.
- [ ] `tests/test_ci_workflow.py` sprawdza obecność pliku, wyzwalacze, kroki oraz brak `secrets.` w treści.
- [ ] Test sprawdza, że `timeout-minutes` jest ustawiony i wynosi najwyżej 15.

## Verification
```bash
uv run pytest tests/test_ci_workflow.py -q
uv run python -c "import yaml,pathlib; print(yaml.safe_load(pathlib.Path('.github/workflows/gate.yml').read_text())['jobs'])"
./scripts/gate.sh; echo "exit=$?"
```
